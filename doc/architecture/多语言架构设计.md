# Flutter 多语言架构设计

> 目标：让 App 壳、游戏 UI、远程配置和后续新增模块都能统一支持多语言，同时保持 packages 边界清晰，避免文案散落在 Widget、runtime 或远程 JSON 里。

## 1. 技术选型

推荐使用 Flutter 官方本地化方案：

- `flutter_localizations`：Flutter SDK 官方本地化 delegate。
- `intl`：日期、数字、复数、占位符格式化。
- `gen_l10n`：由 ARB 生成类型安全的 Dart 访问类。
- ARB 文件：作为本地静态文案源。

不建议第一版使用自研本地化解析器，也不建议在业务 Widget 中手写 `Map<Locale, String>`。

## 2. 包职责

当前工程是 App 壳 + packages，建议新增一个本地 package：

```text
packages/
  app_i18n/
    l10n.yaml
    lib/
      app_i18n.dart
      src/l10n/
        app_en.arb
        app_zh.arb
```

职责划分：

- `lib/app/`：持有当前 Locale、注册 localizations delegates、处理系统语言和用户选择。
- `packages/app_i18n/`：放通用文案、生成的 `AppLocalizations`、支持语言列表。
- `packages/grass_game_ui/`：只读取 `AppLocalizations` 或接收已本地化文案；不维护自己的路由或全局 Locale。
- `packages/grass_game_domain/`：不依赖本地化，不存 UI 展示文案。
- `packages/grass_game_runtime/`：不依赖本地化，不直接生成展示字符串。
- `packages/grass_game_data/`：只处理接口字段和多语言配置 DTO，不决定 UI 展示语言。

依赖方向：

```text
app
  -> app_i18n
  -> grass_game_ui

grass_game_ui
  -> app_i18n
  -> grass_game_domain
  -> grass_game_runtime

domain/runtime/data
  不依赖 Flutter localizations
```

## 3. 目录建议

```text
lib/
  app/
    app.dart
    locale/
      locale_controller.dart
      locale_repository.dart

packages/
  app_i18n/
    l10n.yaml
    lib/app_i18n.dart
    lib/src/l10n/app_en.arb
    lib/src/l10n/app_zh.arb

  grass_game_ui/
    lib/src/presentation/
      pages/
      widgets/
```

`app_i18n.dart` 只暴露稳定 API：

```dart
export 'src/generated/app_localizations.dart';
export 'src/supported_locales.dart';
```

不要让业务包直接 import 生成目录深层路径。

## 4. Locale 管理

Locale 来源按优先级：

1. 用户手动选择的语言。
2. 系统语言。
3. 默认语言，建议 `zh` 或产品默认市场语言。

建议模型：

```dart
enum AppLocaleMode {
  system,
  zh,
  en,
}
```

App 启动流程：

```text
LocaleRepository
  -> 读取本地用户选择
  -> LocaleController
  -> MaterialApp.router(locale/delegates/supportedLocales)
```

存储策略：

- 用户选择存在本地 key-value，例如 `app_locale_mode`。
- `system` 模式不存具体语言，只跟随系统。
- 切换语言后重建根 `MaterialApp.router`，不要在局部页面强刷。

## 5. 文案分类

### 5.1 本地静态文案

放在 `app_i18n` ARB：

- App 标题。
- 通用按钮：确认、取消、继续、暂停、重试。
- 游戏 HUD 静态标签：HP、Lv、Time、Kills。
- 升级弹窗标题、结算页标题、错误兜底文案。

### 5.2 玩法配置名

敌人名、技能名、武器名有两种方式：

第一版推荐本地 ARB：

```text
skill_arrow_name
skill_arrow_desc
enemy_basic_name
weapon_bow_name
```

优点是类型安全、离线可用、审核稳定。

### 5.3 远程活动文案

活动标题、运营文案、奖励说明可以远程下发，但必须带语言维度：

```json
{
  "title": {
    "zh": "限时挑战",
    "en": "Limited Challenge"
  }
}
```

读取规则：

```text
请求当前语言文案
  -> 没有则 fallback 默认语言
  -> 再没有则 fallback 本地兜底文案
```

远程文案不能影响核心玩法规则；玩法规则仍走结构化配置。

## 6. 命名规范

ARB key 使用稳定、语义化、模块前缀：

```text
appTitle
commonConfirm
commonCancel
grassGameReady
grassGameHudHp
grassGameHudLevel
grassGameHudTime
grassGameResultKills
grassGameSkillArrowName
grassGameSkillArrowDesc
```

规则：

- 不用页面临时布局命名，例如 `text1`、`button2`。
- key 一旦上线不要随意改名，避免翻译记忆和远程映射失效。
- 占位符必须写清类型和示例。

示例：

```json
{
  "grassGameResultKills": "Kills {count}",
  "@grassGameResultKills": {
    "placeholders": {
      "count": {
        "type": "int",
        "example": "12"
      }
    }
  }
}
```

## 7. Widget 使用规范

在 Flutter UI 中读取：

```dart
final l10n = AppLocalizations.of(context);
```

规则：

- Widget 里不能写面向用户的裸字符串。
- 允许 debug-only 文案用英文，但必须标注 debug 或只在 debug 面板出现。
- domain/runtime/data 层不能 import `AppLocalizations`。
- 如果某个纯 Dart service 需要展示文案，传入已经本地化后的字符串或 message id，不传 `BuildContext`。

## 8. 日期、数字、单位

所有展示层格式化都走 `intl` 或 Flutter localizations：

- 时间：按语言和地区格式化，不手写 `yyyy-MM-dd` 到处散落。
- 数字：金币、分数、伤害量可保留游戏格式，但千分位和小数规则要统一。
- 单位：秒、分钟、等级等展示文本走 ARB，不拼接硬编码中文。

避免：

```dart
'时间 ${seconds}s'
'击杀 $count'
```

推荐：

```dart
l10n.grassGameTime(seconds)
l10n.grassGameResultKills(count)
```

## 9. 多语言与游戏配置

领域层配置只存稳定 id：

```dart
class SkillConfig {
  final String id;
}
```

展示层通过 id 查本地化文案：

```text
SkillConfig(id: "arrow")
  -> grassGameSkillArrowName
  -> grassGameSkillArrowDesc
```

这样可以保证：

- 玩法配置不受语言影响。
- runtime 不需要关心语言。
- 远程配置只传 id 和数值，降低多语言错误风险。

## 10. 测试策略

最低测试：

- `flutter analyze`
- `flutter test`
- 至少一条 Widget test 覆盖默认语言渲染。
- 至少一条 Widget test 覆盖英文或中文 Locale 强制渲染。

手工检查：

- 系统中文、英文启动。
- App 内切换语言后路由和页面刷新正常。
- 文案长度变长时 HUD、按钮、弹窗不溢出。
- 远程文案缺失时 fallback 正常。

## 11. 实施阶段

### 阶段 1：基础接入

- 新增 `app_i18n` package。
- 配置 `flutter_localizations`、`intl`、`gen_l10n`。
- 增加 `zh`、`en` 两套 ARB。
- 根 App 使用 `MaterialApp.router` 注册 delegates 和 supportedLocales。

### 阶段 2：替换硬编码文案

- 替换 App 标题。
- 替换 `grass_game_ui` 中 HUD、Ready、结算、按钮文案。
- 测试中文/英文 Locale。

### 阶段 3：语言切换

- 新增 `LocaleController` 和本地持久化。
- 设置页或 debug 入口增加语言切换。
- 支持 `system`、`zh`、`en`。

### 阶段 4：远程文案

- 活动文案 DTO 支持语言 map。
- data 层做 fallback。
- UI 层只消费最终展示文本或 message id。

## 12. 禁止事项

- 禁止业务 Widget 直接写面向用户的硬编码文案。
- 禁止 domain/runtime 持有 `BuildContext` 或 `AppLocalizations`。
- 禁止远程配置只下发单语言运营文案。
- 禁止用语言文案作为业务 id。
- 禁止在 Component 或 System 内做日期、数字、语言格式化。
