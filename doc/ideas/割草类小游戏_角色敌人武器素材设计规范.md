# 割草类小游戏角色、敌人、武器素材设计规范

> 用途：给设计师、外包、美术同学或 AI 生图流程使用，明确这款 Flutter + Flame 割草小游戏需要哪些图片、去哪里设计、怎么命名、怎么交付、怎么放进工程。
>
> 当前项目的人物、普通怪兽、Boss spritesheet 接入细则见：`doc/ideas/割草类小游戏_人物怪兽图片接入规范.md`。新增角色或怪兽时，以该文件的帧尺寸、方向行、锚点和验收清单为准。
>
> 新武器的图标、弹体、拖尾、命中和地面残留特效细则见：`doc/ideas/割草类小游戏_武器图片与打击特效素材规范.md`。

---

## 1. 美术方向建议

### 推荐风格

优先选择：

```text
Q 版扁平 2D
或
轻像素风
```

原因：

- App 内小游戏需要识别快、画面干净。
- 敌人和子弹很多，素材不能太复杂。
- Q 版和像素风容易批量生产。
- 动画帧成本可控。
- 低端机渲染压力较小。

不建议 MVP 使用：

- 写实厚涂。
- 高复杂度 3D。
- 复杂骨骼动画。
- 大量透明粒子叠加。

## 2. 主题方向

### 方向 A：奇幻森林

适合通用小游戏。

| 类型 | 例子 |
| --- | --- |
| 主角 | 小勇者、小魔法师、小弓手 |
| 敌人 | 史莱姆、蘑菇怪、蝙蝠、虫群 |
| 武器 | 弓箭、飞镖、火焰、激光魔法 |
| 背景 | 草地、森林、遗迹 |

### 方向 B：学习守卫战

适合学习类 App 或教育活动。

| 类型 | 例子 |
| --- | --- |
| 主角 | 学习小英雄、知识守卫者、能量少年 |
| 敌人 | 拖延怪、错题怪、困困怪、分心怪 |
| 武器 | 知识箭、专注飞镖、灵感激光、记忆光环 |
| 背景 | 书桌、知识星球、训练场 |

### 方向 C：科幻训练场

适合更酷的战斗风。

| 类型 | 例子 |
| --- | --- |
| 主角 | 小机器人、宇航员、机甲少年 |
| 敌人 | 无人机、机械虫、故障机器人 |
| 武器 | 能量弹、激光、环绕无人机、电磁场 |
| 背景 | 训练场、太空甲板、数据空间 |

## 3. 去哪里设计

### 3.1 UI、HUD、技能卡

推荐工具：

- Figma。
- Pixso。
- 蓝湖。

适合设计：

- 游戏首页。
- HUD：血条、经验条、等级、时间、击杀。
- 升级三选一弹窗。
- 技能卡。
- 暂停弹窗。
- 结算页。
- 按钮、图标、边框。

如果后续要按蓝湖设计还原到当前 Flutter 工程，需要先读取蓝湖标注和切图，再按工程规则落到资源目录。

### 3.2 像素角色、敌人、武器

推荐工具：

- Aseprite。
- Piskel。
- LibreSprite。

适合设计：

- 像素主角。
- 像素敌人。
- 像素飞镖、箭矢、宝石。
- spritesheet 动画。

优点：

- 动画帧好管理。
- 输出 PNG/spritesheet 方便。
- 适合 Flame 使用。

### 3.3 Q 版 2D 角色

推荐工具：

- Photoshop。
- Illustrator。
- Procreate。
- Clip Studio Paint。

适合设计：

- Q 版主角。
- 扁平 2D 敌人。
- 技能图标。
- 背景图。

### 3.4 AI 辅助生成

可用工具：

- Midjourney。
- Stable Diffusion。
- DALL-E / ChatGPT image generation。
- 即梦。
- 通义万相。

建议用途：

- 风格探索。
- 静态角色概念图。
- 敌人概念图。
- 技能图标草稿。
- 背景氛围图。

不建议直接用于：

- 连续动作 spritesheet。
- 多方向完全一致的角色动画。
- 正式上线素材，除非已经确认授权并人工修图统一。

### 3.5 素材库

适合 Demo 或预算有限时使用。

| 渠道 | 用途 | 注意 |
| --- | --- | --- |
| Kenney | 免费/低成本游戏素材 | 风格偏通用，适合 Demo |
| itch.io Game Assets | 像素/2D 素材多 | 必须看 license |
| OpenGameArt | 开源素材 | 必须确认是否可商用、是否署名 |
| GameArt2D | 商用 2D 素材 | 风格要统一 |
| Unity Asset Store | 可找 2D 素材 | 确认授权能否用于 Flutter 游戏 |

## 4. MVP 素材清单

### 4.1 角色

| 素材 | 数量 | 规格建议 | 说明 |
| --- | ---: | --- | --- |
| 主角 idle | 4-6 帧 | 96x96 | 呼吸/待机 |
| 主角 move | 6-8 帧 | 96x96 | 默认朝右，游戏内镜像 |
| 主角 hit | 1-2 帧 | 96x96 | 可选 |
| 主角 dead | 4-6 帧 | 96x96 | MVP 可先不做 |

### 4.2 敌人

| 素材 | 数量 | 规格建议 | 说明 |
| --- | ---: | --- | --- |
| 普通怪 walk | 4-6 帧 | 64x64 | 基础追踪怪 |
| 快速怪 walk | 4-6 帧 | 48x48 或 64x64 | 体型小 |
| 厚血怪 walk | 4-6 帧 | 96x96 | 体型大 |
| 敌人 hit | 1 帧 | 同尺寸 | 可用闪白替代 |
| 敌人 dead | 4-6 帧 | 同尺寸 | MVP 可先用消散特效 |

### 4.3 武器和技能

| 素材 | 数量 | 规格建议 | 说明 |
| --- | ---: | --- | --- |
| 箭矢 | 1-2 张 | 32x32 或 64x64 | 可旋转 |
| 旋转飞镖 | 1 张或 4 帧 | 48x48 | 环绕玩家 |
| 激光中段 | 1 张 | 32x128 | 可拉伸 |
| 激光端点 | 1 张 | 64x64 | 可选 |
| 火焰圈 | 4-8 帧 | 256x256 | 后续 |
| 雷电链 | 2-4 张 | 可拉伸 | 后续 |
| 爆炸/命中特效 | 4-8 帧 | 64x64 | 可选 |

### 4.4 掉落物

| 素材 | 数量 | 规格建议 | 说明 |
| --- | ---: | --- | --- |
| 小经验宝石 | 1-4 帧 | 32x32 | 蓝/绿 |
| 中经验宝石 | 1-4 帧 | 40x40 | 紫 |
| 大经验宝石 | 1-4 帧 | 48x48 | 金 |
| 磁铁道具 | 1 张 | 64x64 | 后续 |
| 回血道具 | 1 张 | 64x64 | 后续 |

### 4.5 UI 图标

| 素材 | 数量 | 规格建议 | 说明 |
| --- | ---: | --- | --- |
| 技能图标 | 8-12 张 | 128x128 | 弓箭、飞镖、激光等 |
| 暂停图标 | 1 张 | 64x64 | Flutter 也可直接画 |
| 继续图标 | 1 张 | 64x64 | 可选 |
| 生命图标 | 1 张 | 64x64 | 可选 |
| 经验图标 | 1 张 | 64x64 | 可选 |

| 素材 | 数量 | 规格建议 | 说明 |
| --- | ---: | --- | --- |
| 可平铺地面 | 1 张 | 512x512 或 1024x1024 | 草地/训练场 |
| 装饰物 | 5-10 张 | 64x64/128x128 | 石头、草丛、书本等 |

## 5. 命名规范

统一使用：

```text
英文小写
下划线
无空格
无中文
无特殊符号
```

示例：

```text
player_idle_00.png
```

## 6. 交付格式

### 6.1 图片

推荐：

- PNG，透明背景。
- spritesheet + json。
- 图标单张 PNG。

可选：

- WebP，包体更小，但需确认 Flutter/目标平台兼容。

不建议：

- JPG 用于角色、敌人、图标。
- PSD/AI 源文件直接放进工程。
- 超大未压缩 PNG。

### 6.2 音效

推荐：

- `mp3`。
- `ogg`，如目标平台确认支持。
- 单个短音效尽量小于 100KB。

必备音效：

- 射击。
- 命中。
- 敌人死亡。
- 经验拾取。
- 升级。
- 技能选择。
- 玩家受击。
- 结算。

## 7. Flutter 工程放置建议

### 7.1 只给小游戏使用

放在：

```text
my_flutter_module/assets/game/grass_game/
  images/
    player/
    enemies/
    effects/
    drops/
    ui/
    icons/
  audio/
    sfx/
    bgm/
  atlas/
```

`my_flutter_module/pubspec.yaml`：

```yaml
flutter:
  assets:
    - assets/game/grass_game/images/
    - assets/game/grass_game/audio/
    - assets/game/grass_game/atlas/
```

### 7.2 多模块复用

放在：

```text
res_common/assets/image/
```

然后运行：

```bash
cd res_common
./scripts/run_image_generate.sh
```

代码中通过 `ImageAssets` 引用。

### 7.3 哪些不应该放进工程

- `.psd`
- `.ai`
- `.sketch`
- `.fig`
- `.DS_Store`
- 设计过程截图。
- 未使用的大图。
- 多余导出版本。
- 无授权来源的素材。

## 8. 给设计师的需求模板

可以直接复制给设计师：

```text
需要设计一套 Flutter + Flame App 内割草小游戏素材。

游戏视角：2D 俯视或轻俯视。
画风：Q 版扁平 2D / 轻像素风。
背景：透明 PNG，游戏内自行叠加背景。
主角默认朝右，游戏内可水平镜像。

第一批素材：
1. 主角 idle 4-6 帧，96x96。
2. 主角 move 6-8 帧，96x96。
3. 普通怪 walk 4-6 帧，64x64。
4. 快速怪 walk 4-6 帧，64x64。
5. 厚血怪 walk 4-6 帧，96x96。
6. 箭矢 1 张，64x64。
7. 旋转飞镖 1 张或 4 帧，64x64。
8. 激光 body/head，可拉伸。
9. 小/中/大经验宝石，各 1-4 帧。
10. 技能图标 8-12 张，128x128。
11. 可平铺背景 1 张，512x512 或 1024x1024。

命名要求：
英文小写 + 下划线，不要中文、空格、特殊符号。

交付：
PNG 透明背景。
如有动画，请同时给 spritesheet 和帧说明。
请说明素材是否原创、是否可商用、是否需要署名。
```

## 9. AI 生图提示词方向

### 9.1 主角

```text
Q版小弓手，2D手机小游戏角色，俯视角，简洁轮廓，明亮配色，适合透明背景sprite，动作可爱，儿童友好，游戏asset style
```

英文：

```text
cute chibi archer hero, 2D mobile game sprite, top-down view, clean silhouette, bright colors, transparent background, kid-friendly, game asset style
```

### 9.2 敌人

```text
Q版史莱姆小怪，2D手机游戏敌人，俯视角，简单轮廓，可爱但有敌意，透明背景，适合sprite动画
```

英文：

```text
cute slime monster enemy, 2D mobile game sprite, top-down view, simple silhouette, slightly hostile, transparent background, sprite animation asset
```

### 9.3 武器图标

```text
Q版技能图标，魔法激光，手机游戏UI图标，128x128，清晰轮廓，高对比，透明背景，fantasy skill icon
```

英文：

```text
fantasy laser skill icon, mobile game UI, 128x128, clean silhouette, high contrast, transparent background, polished game icon
```

### 9.4 注意

AI 出图后必须人工检查：

- 角色方向是否一致。
- 透明背景是否干净。
- 多帧动作比例是否一致。
- 图标风格是否统一。
- 是否有多余文字、水印、奇怪边缘。
- 商用授权是否明确。

## 10. 版权检查清单

每个素材都记录：

| 字段 | 说明 |
| --- | --- |
| 文件名 | 例如 `player_idle_00.png` |
| 来源 | 原创/AI/素材库/外包 |
| 作者 | 设计师或素材作者 |
| 授权 | 是否可商用 |
| 是否需署名 | 是/否 |
| 是否可二次修改 | 是/否 |
| 购买记录 | 链接或订单号 |
| 备注 | 限制说明 |

上线前必须确认：

- 没有未经授权的网络图片。
- 没有带水印素材。
- 没有 license 不明的素材。
- 没有从其他游戏直接截取的角色、怪物、图标。

## 11. 最推荐的实际流程

```text
1. 开发先用临时图形跑通玩法
2. 用 AI 或素材库快速探索 2-3 个风格方向
3. 选定一种风格
4. 设计师制作 MVP 素材清单
5. 开发接入 Flame
6. 真机检查尺寸、识别度、性能
7. 再补 hit/dead、Boss、特效、活动皮肤
```

第一版不要追求完整美术。先让游戏闭环好玩，再逐步替换正式资源。
