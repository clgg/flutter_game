# 割草类小游戏人物、怪物素材精准裁切方案

> 用途：解决 AI 生成或外部素材导入时，人物、怪物被裁多、裁少、脚底不齐、播放抖动的问题。后续新增角色、普通怪或 Boss 时，先按本文生成、裁切、归一化和验收，再进入 `assets/game/grass_game/images/`。

## 1. 核心结论

不要把“裁切准确”理解成把每一帧都紧贴透明边界裁到最小。游戏里真正需要的是：

```text
主体边界识别准确
+ 固定单元格
+ 固定脚底锚点
+ 固定身体中心线
+ 同一动作不逐帧缩放
= 播放稳定、碰撞观感一致
```

正确流程是：

1. 先生成或整理出透明背景原图。
2. 用 alpha 通道检测主体真实边界。
3. 去掉噪点、文字、棋盘格、残影。
4. 按主体边界裁出临时图。
5. 重新粘贴到固定单元格。
6. 按脚底线和身体中心线对齐。
7. 最后拼成 spritesheet。

也就是说，裁切只是中间步骤，最终交付永远是固定规格的 normalized sheet。为了降低运行内存，新增 8 方向素材优先使用 `128x128` 单帧；如果需要保留高清可编辑源，再额外归档 `256x256` 源帧，不直接进入运行时 assets。

## 2. 本项目固定规格

当前代码和旧素材里仍有 4 方向、`256x256` 单帧兼容规格；后续如果要做更完整的方向表现，新增素材优先按 8 方向 + 独立攻击动画 + 独立攻击特效交付。接入代码前要确认运行时已经按对应行顺序和单帧尺寸读取，不能把 8 方向素材直接套进旧的 4 方向读取逻辑。

### 2.1 4 方向兼容规格

| 类型 | 最终图片 | 网格 | 单帧 | 锚点 |
| --- | --- | --- | --- | --- |
| 玩家角色 | `1536x1024` | 6列 x 4行 | `256x256` | `x=128`，脚底 `y=238-242` |
| 普通怪物 | `1536x2048` | 6列 x 8行 | `256x256` | `x=128`，脚底 `y=238-242` |
| Boss | `1536x2048` | 6列 x 8行 | `256x256` | `x=128`，脚底 `y=238-242` |

### 2.2 8 方向 + 攻击动画轻量推荐规格

8 方向模式下，每个动作一张独立 spritesheet。不要把 walk 和 attack 混在同一张 sheet 的不同行里，否则后续扩展 idle、hit、dead 时很容易冲突。

新增运行时资源优先使用 `128x128` 单帧。`8方向 x 每方向6帧` 的 sheet 从 `1536x2048` 降到 `768x1024`，RGBA 解码内存大约从 12MB 降到 3MB。walk、attack、attack effect 三张合计约 9MB，比三张 `256x256` sheet 约 36MB 更适合移动端。

| 类型 | 动作 | 推荐命名 | 图片尺寸 | 网格 | 单帧 | 帧数 |
| --- | --- | --- | --- | --- | --- | ---: |
| 玩家角色 | 行走 | `player_<id>_walk_8dir_sheet.png` | `768x1024` | 6列 x 8行 | `128x128` | 每方向6帧 |
| 玩家角色 | 攻击 | `player_<id>_attack_8dir_sheet.png` | `768x1024` | 6列 x 8行 | `128x128` | 每方向6帧 |
| 玩家角色 | 攻击特效 | `player_<id>_attack_effect_8dir_sheet.png` | `768x1024` | 6列 x 8行 | `128x128` | 每方向6帧 |
| 普通怪物 | 行走 | `enemy_<id>_walk_8dir_sheet.png` | `768x1024` | 6列 x 8行 | `128x128` | 每方向6帧 |
| 普通怪物 | 攻击 | `enemy_<id>_attack_8dir_sheet.png` | `768x1024` | 6列 x 8行 | `128x128` | 每方向6帧 |
| 普通怪物 | 攻击特效 | `enemy_<id>_attack_effect_8dir_sheet.png` | `768x1024` | 6列 x 8行 | `128x128` | 每方向6帧 |
| Boss | 行走 | `boss_<id>_walk_8dir_sheet.png` | `768x1024` | 6列 x 8行 | `128x128` | 每方向6帧 |
| Boss | 攻击 | `boss_<id>_attack_8dir_sheet.png` | `768x1024` | 6列 x 8行 | `128x128` | 每方向6帧 |
| Boss | 攻击特效 | `boss_<id>_attack_effect_8dir_sheet.png` | `768x1024` 或 `1152x1536` | 6列 x 8行 | `128x128` 或 `192x192` | 每方向6帧 |

8 方向行顺序固定为从屏幕下方开始，按顺时针排列：

| 行 | 方向 | 屏幕移动/朝向 |
| ---: | --- | --- |
| 0 | front / down / S | 面向屏幕下方 |
| 1 | down_right / SE | 面向右下 |
| 2 | right / E | 面向右 |
| 3 | up_right / NE | 面向右上 |
| 4 | back / up / N | 面向屏幕上方 |
| 5 | up_left / NW | 面向左上 |
| 6 | left / W | 面向左 |
| 7 | down_left / SW | 面向左下 |

方向选择建议按角色移动向量或攻击目标向量计算。攻击动画通常用攻击目标向量；没有目标时沿用当前移动方向或上一次朝向。

安全框：

```text
128x128 cell
  x: 12-116    主体主要活动范围
  y: 4-121     主体主要活动范围
  x: 64        身体中心参考线
  y: 119-121   脚底参考线

256x256 source cell
  x: 24-232    主体主要活动范围
  y: 8-242     主体主要活动范围
  x: 128       身体中心参考线
  y: 238-242   脚底参考线
```

允许头发、角、翅膀、尾巴轻微进入边距，但不能贴边或被裁断。阴影必须留在单元格内，不能决定主体锚点。

攻击动画额外要求：

- 攻击动作可以挥手、挥爪、张口、蓄力，但脚底锚点不能移动。
- 近战武器、爪子、尾巴可以伸出到安全框外，但不能超出单元格。
- 远程攻击的子弹、火球、激光、爆炸不要画进角色攻击帧，应作为独立 projectile/effect 资源。
- 攻击第 1 帧应能自然衔接 walk 或 idle，不要从完全不同的姿势突然开始。
- 攻击最后 1 帧应能回到站立姿态附近，避免循环或切回 walk 时闪跳。

攻击特效额外要求：

- 攻击特效按 8 方向单独做 sheet，行顺序和 walk/attack 完全一致。
- 特效只包含挥砍弧光、爪击轨迹、口喷光、蓄力闪光等视觉效果，不包含角色本体。
- projectile 飞行物仍建议独立为单帧或短动画，不强行塞进 attack effect sheet。
- 普通角色和普通怪默认 `128x128` 单帧；Boss 特效确实需要更大范围时才允许 `192x192`。
- 特效不要大面积半透明铺满整格，同屏数量多时会增加 fill-rate 压力。

## 3. 生成阶段就要避免裁切问题

AI 或设计师出图时，优先要求“固定画布 + 居中 + 留白”，不要要求“紧贴角色裁切”。

推荐描述：

```text
请生成 Flutter + Flame 割草小游戏角色/怪物素材。

运行时画布：每帧固定 128x128 像素；如需高清归档，可额外保留 256x256 源帧。
背景：真透明 RGBA，不要白底、棋盘格、截图背景。
主体：完整身体必须在画布内，不能贴边，不能被裁断。
留白：128x128 运行帧左右至少 12px，上方至少 4px，下方保留 4-9px。
锚点：128x128 运行帧脚底落在同一水平线，约 y=120；身体中心对齐 x=64。
比例：同一角色每帧不要忽大忽小；正面、背面、侧面视觉高度一致。
动作：单张 sheet 只放一个动作；walk sheet 只做 walk 循环，attack sheet 只做攻击动作，不混入跳跃、受击或大招。
禁止：文字、水印、UI圆圈、武器火光、大面积投影、复杂粒子特效。
交付：透明 PNG 分帧或 spritesheet，并保留原始源图。
```

如果一次生成整张 sheet，补充：

```text
玩家角色：输出 1536x1024，6列x4行，每格256x256。行顺序：front、back、left、right。
普通怪/Boss：输出 1536x2048，6列x8行，每格256x256。第5-8行为 walk，行顺序：front、back、left、right。
每个格子必须有清晰边界意识，但最终图片不要画出网格线。
```

如果生成 8 方向 + 攻击动画，使用：

```text
请按 8 方向制作，每个动作单独一张 spritesheet。

单帧：128x128。
整图：768x1024，6列x8行。
行顺序：front/down、down_right、right、up_right、back/up、up_left、left、down_left。
动作：walk 一张 sheet，attack 一张 sheet，attack effect 一张 sheet。
walk：每方向6帧，脚底固定 y=120，身体中心 x=64。
attack：每方向6帧，脚底固定 y=120，身体中心 x=64；只画角色本体攻击动作，不画飞出去的子弹、爆炸、激光或命中特效。
attack effect：每方向6帧，只画攻击轨迹、挥砍弧光、爪击残影、口喷光或蓄力闪光，不画角色本体。
所有方向保持同一角色比例、同一光照、同一描边粗细。
```

## 4. 自动裁切建议算法

推荐用脚本批处理，不要手工一张张拖裁切框。手工裁切很容易因为阴影、尾巴、抗锯齿和视觉判断导致每帧偏差。

### 4.1 输入要求

输入可以是：

- 单帧透明 PNG。
- 多帧透明 PNG。
- 已经排好网格但位置不稳定的 spritesheet。
- 大图中多个角色，需要先人工或工具粗分块。

输入不建议是：

- JPG。
- 带白底或棋盘格的截图。
- 已经压缩到很小、边缘糊掉的图。
- 带文字、水印、UI 框的图。

### 4.2 边界检测

按 alpha 通道取主体，不按肉眼矩形裁切：

```text
1. 读取 RGBA。
2. alpha >= 16 的像素视为可见像素。
3. 删除面积很小的连通区域，避免噪点扩大边界。
4. 如果有半透明阴影，用 alpha >= 32 或颜色饱和度辅助识别主体边界。
5. 取最大主体连通区域 bbox。
6. bbox 四周加 4-8px 安全 padding。
```

注意：

- 阴影可以保留，但不要用阴影的最外边缘计算身体中心。
- 武器火花、粒子、拖尾如果不是角色本体，应删除或独立做特效资源。
- 尾巴、翅膀属于主体，但不能让它们改变脚底锚点。

### 4.3 归一化粘贴

每帧不要直接输出 bbox 尺寸，而是重新粘贴到固定单元格。运行时推荐 `128x128`，高清源帧可保留 `256x256`：

```text
target_cell = 128x128
center_x = 64
foot_y = 120

body_bbox = 主体边界
body_center_x = body_bbox.center_x
body_bottom_y = body_bbox.bottom

paste_x = center_x - body_center_x
paste_y = foot_y - body_bottom_y
```

同一动作循环内：

- 可以逐帧裁 bbox。
- 不能逐帧重新缩放到同一高度。
- 缩放比例必须按同一个角色、同一个方向统一决定。
- 脚底线差异控制在 4px 内。
- 躯干中心差异控制在 6px 内。

如果某一帧因为抬腿导致真实最低点变化，应以“支撑脚脚底”对齐，而不是以摆动腿或阴影最低点对齐。

### 4.4 攻击动画归一化

攻击动画不能按“攻击伸出的最远点”重新居中，否则角色会在挥刀、挥爪、张口时左右漂。攻击帧需要拆分两个概念：

```text
角色本体 bbox：身体、头、脚、躯干，用于中心和脚底锚点。
攻击动作 bbox：手臂、武器、爪子、尾巴，用于检查是否越界。
```

归一化时：

1. 以角色本体脚底对齐 `foot_y=120`。
2. 以角色本体中心对齐 `center_x=64`。
3. 武器、爪子、尾巴随角色一起移动，不参与重新居中。
4. 如果攻击动作越界，优先缩短武器/特效，其次统一缩小整套方向，不要单帧单独缩放。
5. 同一方向的 attack 第 1 帧和最后 1 帧应与 walk/idle 的脚底线和身体中心一致。

### 4.5 攻击特效归一化

攻击特效不参与角色锚点计算，但必须和角色同方向、同帧数、同节奏：

```text
effect_cell = 128x128
effect_center_x = 64
effect_action_origin = 角色攻击发力点附近
```

归一化时：

1. 特效 sheet 行顺序必须与 walk/attack 完全一致。
2. 每方向 6 帧，与 attack 同步播放。
3. 第 1 帧通常为预备或刚出现的弱特效，不要突然满屏。
4. 第 3-4 帧通常为最强帧。
5. 最后 1 帧应自然消散，避免循环闪烁。
6. 特效可以围绕攻击方向偏移，但同方向每帧不能忽左忽右。
7. 远程飞行物独立做 projectile，不放进 attack effect。

## 5. 最容易出错的情况

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 裁多了，头发/角/尾巴被切 | 生成时主体贴边，或 bbox 后没有 padding | 重新生成时要求留白；裁切时加 4-8px padding |
| 裁少了，周围空白太大 | 把整张画布直接缩放进单元格 | 先取 alpha bbox，再按脚底线粘贴回固定单元格 |
| 播放时上下跳 | 每帧按最小 bbox 居中，没对齐脚底 | 128运行帧固定 `foot_y=120` |
| 播放时左右漂 | 每帧按含武器/尾巴的 bbox 居中 | 128运行帧用躯干中心或身体主区域中心对齐 `x=64` |
| 人物忽大忽小 | 每帧单独缩放 | 同一角色同一动作只允许统一缩放比例 |
| 白边/棋盘格残留 | 背景不是真透明 | 重新抠图，确认 alpha 通道 |
| 碰撞看起来不准 | 图像占满格子或脚底锚点不一致 | 保留安全边距，统一脚底线和视觉体积 |

## 6. 手工检查方法

每次新素材接入前，至少做一张验收预览图：

```text
1. 给每个 128x128 单元格叠加参考线：
   - x=64 中心线
   - y=120 脚底线
   - x=12 和 x=116 安全边界
   - y=4 和 y=121 安全边界

2. 导出 walk GIF、attack GIF 和 attack effect GIF，肉眼检查：
   - 是否上下跳。
   - 是否左右漂。
   - 是否忽大忽小。
   - 是否方向比例不一致。
   - 是否有残留背景或白边闪烁。
   - attack 首尾是否能自然接回 walk/idle。
   - attack effect 是否与 attack 同方向、同节奏。
```

验收阈值：

| 检查项 | 合格标准 |
| --- | --- |
| 脚底线 | 同一行动画差异不超过 4px |
| 躯干中心 | 同一行动画差异不超过 6px |
| 头顶高度 | 同一行动画差异不超过 8px |
| 主体边距 | 128帧左右至少 12px，上方至少 4px，下方 4-9px |
| 体型变化 | 同一动作循环高度变化不超过 5% |
| 方向比例 | front/back/left/right 视觉身高差异不超过 10% |

## 8. 给 AI 的精确裁切提示词

### 8.1 单帧角色

```text
生成一个 2D 轻俯视 Q版游戏角色 sprite，透明背景 PNG。
运行时画布固定 128x128 像素，角色完整身体位于画布内。
角色身体中心对齐 x=64，双脚脚底对齐 y=120。
左右至少 12px 留白，顶部至少 4px 留白，底部保留 4-9px。
不要贴边，不要裁断头发、武器、尾巴、角或脚。
不要白底、棋盘格背景、文字、水印、UI边框、地面光圈。
轮廓清晰，适合手机小游戏 52x52 左右显示。
```

### 8.2 多帧 walk

```text
生成同一个角色的 walk 动画分帧，透明背景 PNG。
每帧都是固定 128x128 像素，不要紧贴主体裁切。
所有帧使用相同角色比例、相同视角、相同光照和描边。
每帧身体中心保持 x=64，支撑脚脚底保持 y=120。
动画可以摆臂和迈腿，但躯干不要左右漂移，头顶不要上下跳。
输出 6 帧 walk 循环。
```

### 8.3 spritesheet

```text
生成 Flutter + Flame 割草小游戏 spritesheet。
整图透明 PNG，不要背景，不要网格线。
每个单元格固定 128x128，主体不能贴边。
每帧身体中心 x=64，脚底 y=120。
同一行所有帧比例一致，脚底线一致，不要忽大忽小。
```

### 8.4 8 方向 walk + attack + attack effect

```text
生成 Flutter + Flame 割草小游戏 8方向角色动画素材，透明 PNG spritesheet。

需要三张独立 sheet：
1. walk：player_<id>_walk_8dir_sheet.png
2. attack：player_<id>_attack_8dir_sheet.png
3. attack effect：player_<id>_attack_effect_8dir_sheet.png

每张 sheet 固定 768x1024，6列x8行，每格128x128。
行顺序固定为：
第1行 front/down
第2行 down_right
第3行 right
第4行 up_right
第5行 back/up
第6行 up_left
第7行 left
第8行 down_left

每个方向 6 帧。
每帧身体中心 x=64，脚底 y=120。
walk 只表现移动循环。
attack 只表现角色本体攻击动作，可以挥手、挥爪、张口、蓄力，但不要画飞出的子弹、爆炸、激光、命中特效。
```
