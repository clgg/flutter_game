# 割草类小游戏人物、怪兽图片接入规范

> 用途：约束玩家角色、普通怪、Boss 的 spritesheet 交付格式。下次新增角色或怪兽时，先按本文验收素材，再接入代码，避免动画闪烁、方向错误、背景残留和碰撞观感不一致。
>
> 注意：本文保留当前代码和旧素材的 `256x256`、4方向/兼容规格。后续新增 8 方向、攻击动画、攻击特效和轻量运行图时，以 `doc/ideas/割草类小游戏_人物怪物素材精准裁切方案.md` 为准；推荐运行时单帧为 `128x128`，高清 `256x256` 源帧只做设计归档。

## 1. 通用硬性要求

| 项目 | 要求 |
| --- | --- |
| 文件格式 | 游戏内行走动画统一用 PNG spritesheet。头像、预览图可用 WebP/GIF。 |
| 透明背景 | 必须是真透明 RGBA，不要棋盘格背景、白底、截图底、阴影底。 |
| 单帧尺寸 | 玩家和新怪兽统一按 `256x256` 单元格制作。旧怪兽压缩图只做兼容，不作为新素材模板。 |
| 帧排列 | 横向放帧，纵向放方向。每行帧数固定。 |
| 主体锚点 | 每一帧人物或怪兽脚底必须在同一条水平线上，身体中心必须基本对齐。 |
| 安全边距 | 主体不要贴边，建议左右至少 24px，上方至少 8px，下方保留 8-18px。 |
| 阴影 | 阴影必须跟随主体在同一帧内，不允许跨出单元格，也不要用大面积半透明模糊阴影。 |
| 风格 | 同一批角色和怪兽视角、描边粗细、明暗方向、饱和度要一致。 |
| 授权 | 来源、作者、授权、是否可商用、是否需署名必须可追溯。 |

最容易返工的问题：

- 把带棋盘格背景的预览图当透明图交付。
- 每帧主体在 `256x256` 格子里的位置不一致，播放时会抖动或闪。
- 不同方向的角色比例不一致，侧面比正面大很多或小很多。
- 把多张动作截图拼成 sheet，但没有统一裁切和脚底锚点。
- 图片里自带枪、火焰、文字、水印，和游戏运行时子弹、特效叠加后冲突。

## 2. 玩家角色规格

当前玩家动画由 `PlayerAnimationSet` 读取，默认规格如下：

| 项目 | 规格 |
| --- | --- |
| 文件位置 | `assets/game/grass_game/images/player/` |
| 文件名 | `player_<角色id>_walk_sheet.png` |
| 图片尺寸 | `1536x1024` |
| 网格 | 6 列 x 4 行 |
| 单帧 | `256x256` |
| 行顺序 | 第 1 行正面/向下，第 2 行背面/向上，第 3 行向左，第 4 行向右 |
| 每行动画 | 6 帧 walk 循环 |
| 游戏显示尺寸 | 当前运行时约 `52x52`，所以轮廓必须清晰，细节不要过碎。 |

方向定义按屏幕坐标理解：

| 行 | 方向 | 说明 |
| ---: | --- | --- |
| 0 | front | 面向屏幕下方，玩家向下移动时播放。 |
| 1 | back | 面向屏幕上方，玩家向上移动时播放。 |
| 2 | left | 面向左侧，玩家向左移动和左斜移动时播放。 |
| 3 | right | 面向右侧，玩家向右移动和右斜移动时播放。 |

玩家角色制作要求：

- 每行 6 帧必须是同一动作循环，不要混入攻击、受击、跳跃、大招动作。
- 不要把武器绘制成持续可见的大物件；当前游戏射击只展示子弹。
- 正面、背面、侧面高度要一致，脚底线建议固定在 `y=238-242` 附近。
- 主体中心建议固定在 `x=128` 附近，允许动作摆臂轻微偏移，但躯干不能左右漂移。
- 头顶、脚底、肩宽每帧变化不能过大；动画可以动，但角色本体不能跳。
- 头像优先从正面第 1 帧裁切，命名为 `avatar_<角色id>.webp`。
- 选择页预览 GIF 用同一份 normalized sheet 生成，命名为 `preview_<角色id>_walk.gif`。

可选扩展：

- 代码支持 8 行方向图，但当前项目先按 4 方向交付。不要临时用阴影或叠图伪造 8 方向。
- 如果未来真做 8 方向，需要重新定义整套行顺序，并同步修改本文和运行时代码。

## 3. 普通怪兽规格

当前普通怪兽动画由 `EnemyAnimationSet` 读取，默认规格如下：

| 项目 | 规格 |
| --- | --- |
| 文件位置 | `assets/game/grass_game/images/guaishou/` 或按类型放在 `enemies/` |
| 文件名 | `enemy_<怪物id>_walk_sheet.png` 或 `guaishou_<怪物id>_walk_sheet.png` |
| 图片尺寸 | 新素材统一 `1536x2048`。 |
| 网格 | 6 列 x 8 行 |
| 单帧 | `256x256` |
| 运行时使用帧 | 每个方向只使用前 4 帧 |
| 运行时使用行 | 第 5-8 行是 walk：front、back、left、right |

注意：项目里现有少量 `1536x1024` 怪兽图属于旧的压缩规格，运行时会按 6 列 x 8 行读取成 `256x128` 帧。后续新增怪兽不要继续使用这种尺寸，避免和玩家、Boss 的锚点规则不一致。

普通怪兽行顺序：

| 行 | 方向/用途 | 说明 |
| ---: | --- | --- |
| 0-3 | 预留 | 可放 idle 或保持与 walk 对应方向一致，但当前运行时不使用。 |
| 4 | front walk | 向屏幕下方。 |
| 5 | back walk | 向屏幕上方。 |
| 6 | left walk | 向左。 |
| 7 | right walk | 向右。 |

普通怪兽制作要求：

- 小怪同屏数量很多，轮廓要强，局部细节要少。
- 不能每帧改变整体大小；体型变化应控制在 5% 以内。
- 快速怪可以更小，但要保留明显颜色或剪影差异。
- 厚血怪可以更大，但不能占满 `256x256`，否则碰撞观感会比图像小。
- 不要带复杂投影、长尾焰、大范围光效，这些会影响同屏性能和识别。
- 如果素材只做 4 行，需要先转换成当前 8 行结构，不能直接接入。

## 4. Boss 规格

Boss 体积约为玩家 4 倍，当前运行时显示尺寸约 `104x104`。

| 项目 | 规格 |
| --- | --- |
| 文件位置 | `assets/game/grass_game/images/bosses/` |
| 行走命名 | `boss_<bossid>_walk_runtime.png` |
| 8 方向行走命名 | `boss_<bossid>_walk_8dir_sheet.png` |
| 8 方向攻击命名 | `boss_<bossid>_attack_8dir_sheet.png` |
| 8 方向攻击效果命名 | `boss_<bossid>_attack_effect_8dir_sheet.png` |
| 运行时图片尺寸 | `768x1024` |
| 运行时网格 | 6 列 x 8 行，单帧 `128x128` |
| 死亡图片 | 不再单独接入旧 `dead.png`；死亡表现由运行时特效或后续 death sheet 统一补充 |
| 行顺序 | 和普通怪兽一致，第 5-8 行为 walk：front、back、left、right |

Boss 制作要求：

- Boss 可以更细，但游戏中实际显示仍较小，必须先保证剪影和主色块清晰。
- 头、身体、武器或翅膀不能频繁跨越单元格边缘。
- 死亡图应保持同一角色、同一透视、同一比例，不要换成完全不同姿态或画风。
- Boss 不要自带红圈、警戒圈、UI 边框；这类提示由游戏运行时绘制。

## 5. 锚点与裁切标准

每个 `256x256` 单元格都按下面标准验收：

| 检查项 | 合格标准 |
| --- | --- |
| 透明边界 | 单元格边缘不应有残留色块、棋盘格、截图背景。 |
| 脚底线 | 同一行所有帧脚底 y 坐标差异不超过 4px。 |
| 躯干中心 | 同一行所有帧主体中心 x 坐标差异不超过 6px。 |
| 头顶高度 | 同一行所有帧头顶 y 坐标差异不超过 8px。 |
| 角色比例 | 不同方向之间视觉身高差异不超过 10%。 |
| 动作幅度 | 可以摆臂、迈腿，但不能让整个人物在格子内横跳。 |

推荐安全框：

```text
256x256 cell
  x: 24-232  主要可用范围
  y: 8-242   主要可用范围
  x: 128     身体中心参考线
  y: 238-242 脚底参考线
```

如果原始素材主体位置不稳定，必须先做 normalized sheet：

1. 去除背景，只保留最大主体。
2. 按每帧主体真实透明边界裁切。
3. 重新粘贴到 `256x256` 单元格。
4. 水平居中，脚底对齐。
5. 再生成最终 spritesheet、头像和预览 GIF。


## 7. 交付清单

新增一个玩家角色至少交付：

- `player_<id>_walk_sheet.png`
- `avatar_<id>.webp`
- `preview_<id>_walk.gif`
- 原始源文件或可编辑文件，放设计归档，不直接进 Flutter assets。
- 授权说明。

新增一个普通怪兽至少交付：

- `enemy_<id>_walk_sheet.png` 或 `guaishou_<id>_walk_sheet.png`
- 授权说明。
- 怪物定位说明：普通、快速、厚血、远程、特殊。

新增一个 Boss 至少交付：

- `boss_<id>_walk_runtime.png`
- `boss_<id>_attack_8dir_sheet.png`
- `boss_<id>_attack_effect_8dir_sheet.png`
- 授权说明。
- Boss 定位说明：生命值、移动方式、技能提示是否需要运行时特效。

## 8. 接入前验收清单

接入代码前逐项检查：

- 图片尺寸是否符合对应规格。
- 是否为真透明 RGBA。
- 每个方向行数和顺序是否正确。
- 每行帧数是否满足运行时要求。
- 是否没有棋盘格、白边、水印、文字。
- 播放预览 GIF 是否没有闪烁、跳动、忽大忽小。
- 正面、背面、侧面的视觉比例是否一致。
- 游戏显示尺寸下是否能识别角色和怪兽类型。
- 同屏大量怪兽时颜色是否过乱或过暗。
- 是否已确认授权，并记录来源。

建议每次接入后至少做三件事：

```bash
flutter analyze
flutter test
flutter build apk --debug
```

涉及新角色或新怪兽时，还要真机进入战斗页面检查：

- 移动时方向是否正确。
- 静止时是否停在当前方向。
- 射击时人物是否不闪。
- 怪兽追踪玩家时是否不频繁切方向抖动。
- 掉血、血条、碰撞观感是否和图片大小一致。

## 9. 给设计师或 AI 的简短需求模板

```text
请按 Flutter + Flame 割草小游戏规格制作角色/怪兽 spritesheet。

视角：2D 轻俯视，方向统一。
背景：真透明 RGBA，不要棋盘格背景。
单帧：256x256。
玩家角色：1536x1024，6列x4行，行顺序为正面、背面、左、右，每行6帧walk。
普通怪/Boss：1536x2048，6列x8行，第5-8行为walk，顺序为正面、背面、左、右，每方向至少前4帧可用。
锚点：每帧脚底对齐，主体水平居中，不要在格子内跳动。
风格：轮廓清晰，适合手机小尺寸显示，不带文字、水印、UI圈、武器火光特效。
交付：PNG spritesheet + 预览GIF + 授权说明。
```
